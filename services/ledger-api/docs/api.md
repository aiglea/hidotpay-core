# API

正式可機器讀取的規格在 [OpenAPI 文件](../openapi/openapi.yaml)。

## 金額規則

所有金額使用最小單位整數字串，例如 USDT 有 6 位小數時，`1 USDT` 要傳 `"1000000"`。不可傳 `1.0`、`1e6` 或 JavaScript 浮點數。

## 資金流程

| 流程 | 結果 | 鏈上費用 |
|---|---|---|
| 內部轉帳 | 同平台帳戶間即時帳本轉移 | 無鏈上費用 |
| 充值入帳 | 鏈上工作程序確認足夠區塊後才入帳 | 由外部網路收款交易決定 |
| 外部提現 | 先凍結、審核、鏈上確認後結算 | 由平台受控費率計算 |
| P2P 訂單 | 賣方資產先鎖進獨立託管帳戶，再依狀態放幣或退款 | 不產生鏈上費用 |

每一個可重送的請求都必須帶 `Idempotency-Key`。同一把 key 重送會回傳原結果；拿同一把 key 換內容會被拒絕。

## P2P 訂單

1. 賣方建立廣告；廣告只保存支付方式代碼，不能保存銀行帳號或其他個人資料。
2. 買方以 `POST /p2p/orders` 下單；同一筆資料庫交易會驗證廣告限額、確認賣方餘額，並將資產移到該訂單專屬的託管帳戶。
3. 下單回應會提供 `paymentDeadlineAt`。在這個時間前，買方只能標記付款；賣方只能在「等待放幣」時放幣，或在付款前取消並退款。
4. 任一方可以開啟爭議；只有 `p2p_arbitrator` 角色可裁決放幣給買方或退款給賣方。
5. 到期仍為「等待付款」的訂單，私有排程工作每分鐘以可重送的帳本退款返還賣方；已標記付款或已開爭議的訂單絕不會自動退款。

所有 P2P 狀態變更也必須帶 `Idempotency-Key`。付款本身發生在雙方選定的支付管道，平台不接收或顯示帳密、卡號或銀行帳號。
