# hidotpay Figma 錢包引導頁設計

**來源：** Figma `KwXwdMAsvu6ZRpvNXm7WCR`，節點 `1019:16230`（`2. Onboarding - 1`）
**目的：** 將未登入使用者的第一個錢包畫面改為該設計的淺色手機引導頁，同時保留金融產品的安全邊界。

## 已確認的範圍

使用者指定此 Figma 節點作為視覺依據，並已授權直接實作。這一輪只替換未登入／首次進入的頁面；登入後的 `WalletHome` 資產與交易頁不偽裝成此節點，也不會加入假餘額。

## 視覺與版型

- 手機優先的暖白／淺灰背景；上方左側為小型「略過」按鈕。
- 中段有柔和灰色圓形網格裝飾，前景是一張白色、細黑框、圓角的帳戶摘要卡。
- 摘要卡使用 hidotpay 的安全文案取代 Figma 範例中的虛構金額：顯示「安全錢包」與「登入後顯示可用資產」，不可顯示測試數字。
- 兩個螢光黃綠的膠囊操作鈕呈現「轉帳」與「收款」；未登入時是清楚的引導狀態，不會送出資金操作。
- 頁面下半部的白色大圓角引導卡包含 hidotpay 品牌標題、繁中說明、三點分頁指示與螢光黃綠「開始使用」主按鈕。
- 不加入 Figma 未提供的照片、假餘額、鏈上地址、交易編號或私密資訊；不使用 emoji 或手寫 SVG 圖示。

## 互動與安全

- 「略過」與「開始使用」都呼叫既有 Logto 登入流程；登入資料不在 App 內輸入或保存。
- 未登入的「轉帳／收款」僅為視覺導覽，不可點擊、不可呼叫 API。
- 既有登入錯誤、載入狀態與可存取性語意必須保留；主按鈕 busy 時不可重複送出。
- 網頁登入／登出 redirect 延續既有的 HTTPS 動態 origin 保護；正式 Worker 網域必須在 Logto allowlist 設定後才測試實際登入。

## 實作邊界與驗收

- 以既有 Expo／React Native `View`、`Text`、`Pressable`、`StyleSheet` 實作，不引入 Tailwind 或新 UI 套件。
- 先增加會失敗的 component contract tests，再改 `LoginShell`；現有登入頁測試、型別檢查與窄螢幕視覺驗收均需通過。
- 以 Figma 節點截圖做人工比對：375px 寬畫面必須有完整的上方略過、摘要卡、下方引導卡和主按鈕，且不得水平溢出。
- 這是公開 UI 預覽，不是可處理真實資產的生產金流上線；充值、轉帳、提現仍受既有安全開關與發布門檻控制。
