# 充值鏈深度重組事故處置手冊

本手冊適用於掃描器出現 `deep_chain_reorg_detected` 或 `orphaned_credited_deposit_detected`。兩者都是 P0 財務事故訊號：**只停止受影響網路的充值掃描；不得自行修正餘額、回退游標或恢復掃描。** 其他網路須維持原本的監控與風險邊界，不得因本事件被自動開啟資金功能。

## 立即處置

1. 由當班人員建立事故編號，記錄偵測時間（UTC）、受影響網路、錯誤碼、工作程式版本、設定的 `reorgWindow`、最後安全游標的高度與區塊雜湊。
2. 停止該網路的 `DepositScanner` 排程／worker；確認健康檢查為不就緒，並保留原始告警與 worker 日誌。不得只靠重啟消除錯誤。
3. 不得寫入新的掃描游標，不得呼叫充值 creditor，不得將觀測、receipt、`ledger_transactions` 或 `ledger_postings` 改為其他狀態。
4. 資金、提現及人工補帳開關維持關閉；本事故不授權開啟任何真實資產流程。

## 保存可重現證據

在唯讀工作環境中保存下列資料，並以事故編號、取得時間與雜湊保護檔案完整性。證據不得包含服務金鑰、資料庫密碼、使用者個資或助記詞。

- 對至少兩個獨立 RPC 端點保存原始請求與回應：最後安全游標區塊、衝突區塊、目前鏈頭，以及必要範圍的父雜湊鏈。標記端點、區塊高度、區塊雜湊、交易雜湊和取得時間。
- 保存掃描器的設定快照、游標紀錄、錯誤日誌、部署版本／commit SHA，以及從告警到停止掃描的時間線。
- 對每個受影響交易保存 `network + transaction_hash + output_index`（或事件索引）和官方資產、金額最小單位、目標帳戶 ID 的遮罩化對帳清單；不要把地址或帳戶資料貼到公開工單。
- 保存資料庫與 Blnk 的唯讀查詢結果及其匯出雜湊。任何查詢都必須走受限唯讀帳號；不得為取證而執行 migration、回填或更新。

## 四方對帳（只讀）

財務覆核員依同一筆 `(network, transaction_hash, output_index)` 建立對帳表，逐筆比對而不是只看總額。

| 對象 | 必查資料 | 必須確認的關係 |
| --- | --- | --- |
| 鏈上／RPC | 正史區塊、交易／事件、確認數與資產合約 | 事件仍在正史，且屬於允許的官方資產與目標地址。 |
| `deposit_receipts` | receipt ID、金額、資產、目標帳戶、`credited_transaction_id`、Blnk reference／狀態 | 每筆 receipt 對應唯一鏈上事件；已失效觀測不得被當成新充值重播。 |
| `ledger_transactions`／`ledger_postings` | `credited_transaction_id` 對應的不可變交易與完整分錄 | 交易與分錄平衡，且金額、資產及目標帳戶與 receipt 一致；不修改既有紀錄。 |
| Blnk | 以 receipt 的 Blnk reference 或帳本交易 ID 查得的狀態、金額與 reference | Blnk 只是副帳本對帳結果；不得用它覆寫 CockroachDB 不可變總帳。 |

若有任何一方缺失、重複、金額／資產／帳戶不一致，或 RPC 端點對正史沒有一致結論，事件維持未解決，掃描不得恢復。需把差異與證據雜湊加入事故紀錄。

## 禁止動作

- **禁止手動修改總帳。** 不得 `UPDATE`／`DELETE` `ledger_transactions`、`ledger_postings`、使用者餘額或 receipt，也不得新增負數 posting、沖正、人工信用或以 SQL 補差額。
- 不得回退、覆蓋或刪除安全游標；不得把已入帳觀測標成 `orphaned` 來假裝處理完成。
- 不得只因鏈頭恢復正常、單一 RPC 回應正常，或 Blnk 顯示已處理就重啟 worker。
- 不得以正式 `DATABASE_URL` 執行測試、事故重演或資料修復。測試僅能使用獨立 `/hidotpay_test`，且需要另一份明確批准。

## 雙人核准後的恢復

恢復前必須有兩名不同職責的人簽核：一名財務覆核員負責 receipt／不可變總帳／Blnk 對帳，另一名鏈／平台覆核員負責雙 RPC 區塊證據、設定與停機範圍。兩人都必須在事故紀錄中寫明：

1. 受影響事件清單、四方對帳結果與所有未解差異的處置決定；
2. 停止掃描期間沒有新增游標、creditor 呼叫或人工總帳改寫的證據；
3. 要恢復的**單一網路**、恢復時間、設定值、部署版本與回滾方式；
4. 恢復後的加強監控：下一個安全水位、首次掃描批次、receipt／ledger／Blnk 差異與健康檢查。

只有兩份獨立簽核都完成，且主管核准的受控變更已完成時，才可恢復該網路的掃描。恢復後先以最小範圍觀察，保留完整日誌；任何再次出現的重組錯誤立即重新停機並建立新事故。

## 發布與演練門檻

此手冊不代表可以上線真實資產。程式修正必須先在專用 `hidotpay_test` 資料庫完成真實整合驗證；再加上正式鏈節點冗餘、告警、簽名器隔離、備份／還原、測試網深度重組演練與雙人控制證據，才可進入獨立發布審查。
